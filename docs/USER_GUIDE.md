# NetHeal — Interactive User Guide

Welcome to **NetHeal**, the AI-Powered Self-Healing Network Simulator. This user guide explains how to navigate and operate each view in the interactive web dashboard.

---

## 1. Getting Started

1. Ensure both the FastAPI backend (`http://localhost:8000`) and the Vite frontend (`http://localhost:5173`) are running.
2. Open your web browser at `http://localhost:5173`.
3. Check the topbar header:
   - **`FastAPI Online`** (Green badge): The frontend is communicating with the backend simulation engine.
   - **`Backend Offline`** (Red badge): Click "Reconnect" or verify that `uvicorn main:app` is running on port 8000.

---

## 2. Navigating the 5 Application Views

The top navigation bar provides access to five primary views:

### 2.1 Overview Dashboard
- **Key Performance Indicators (KPIs)**:
  - *Active Routers*: Live ratio of operational routers (e.g., `7/7`).
  - *Active Links*: Live ratio of operational transmission links (e.g., `11/11`).
  - *Network Availability*: Global operational percentage.
  - *Mean Latency*: Average latency across all active links.
- **Routing Summary**: Displays the active source and destination (`R1 -> R7`), current selected route, active routing algorithm (BFS, Dijkstra, or ML), and model quality score.
- **Event Feed**: A live chronological log of simulated network events and failure injections.

### 2.2 Network Topology View
- **Interactive Graph Canvas**:
  - Built with `@xyflow/react`.
  - Use mouse wheel to zoom in/out, click and drag to pan across the network.
  - Minimap located in the lower-right corner.
  - Active links are rendered in solid cyan/teal; the active selected route is highlighted with pulsing glow borders.
  - Failed routers or links are highlighted in warning red.
- **Router Details Panel**: Click on any router node (`R1` through `R7`) to inspect its IP address, role (Edge/Core), and incident link capacities.

### 2.3 Failure Simulator
- **Injecting Component Failures**:
  - *Fail Router*: Select a router from the dropdown and click "Fail router". Notice how all links connected to that router automatically become unusable.
  - *Fail Link*: Select a link (e.g., `R5-R7`) and click "Fail link".
- **Dynamic Self-Healing**:
  - As soon as a failure is injected, the backend automatically recalculates a safe alternative route.
  - If a path exists, the new path immediately lights up on the canvas.
  - If the destination is completely disconnected, an alert banner displays: `DESTINATION UNREACHABLE`.
- **Restoration & Reset**:
  - Click "Restore router" or "Restore link" to heal individual components.
  - Click "Reset all failures" to return the topology to its pristine initial state.

### 2.4 Route Analysis
- **Algorithm Switcher**: Choose between:
  - **BFS (Breadth-First Search)**: Optimizes minimum hop count.
  - **Dijkstra**: Optimizes minimum cumulative latency.
  - **ML-Assisted (Random Forest)**: Optimizes multi-metric SLA quality.
- **Route Metrics Panel**: Displays hop count, total latency (ms), bottleneck bandwidth (Mbps), packet loss (%), and ML route quality score.
- **Candidate Routes Table**:
  - When ML routing is active, all feasible loop-free candidate paths are enumerated and scored.
  - The table displays rank, path sequence, latency, loss, bottleneck bandwidth, and predicted quality score (0.0 – 100.0).
- **ML Engine Overview Card**:
  - Displays the model architecture: **Random Forest Regressor (100 Estimators)**.
  - Formatted model accuracy metric: **R² = 0.998**.
  - Highlights input feature vectors used for inference: **Hops**, **Total Latency (ms)**, **Bottleneck Bandwidth (Mbps)**, and **Packet Loss (%)**.

### 2.5 Performance Analytics
- **Live Empirical Benchmarks**: Displays data generated by the 7-scenario experiment suite.
- **Visualized Metrics**:
  - *Latency Comparison*: Bar charts comparing BFS, Dijkstra, and ML route latency across scenarios.
  - *Execution Time Comparison*: High-resolution runtime timing ($0.3 - 0.7$ ms) demonstrating real-time capability.
  - *Link Capacity Breakdown*: Live inspection of bandwidth and packet loss per link.
- **"Run Fresh Benchmark"**: Click the play button to re-run the 7-scenario benchmark suite live against the running backend engine.
